# 配置与本机后台定时任务

## 阶段与边界

Skill 代码可以先修改和离线测试。用户只要求改代码时，到离线测试为止，不提示绑定、不运行付费 API、不安装服务、不更新已安装版本、不重新封装。用户随后要求测试、启用或发布时，再执行相应阶段。

本机运行要求 macOS、Node.js 20+ 与 curl。独立执行入口是 `scripts/background.mjs`，不通过 Codex CLI 或 Codex 自动化唤醒。后台由用户级 launchd 接管，无需管理员权限；需要用户已登录，电脑清醒且网络可用。

## 两项配置即可启动

用户拿到 Skill 后，对 Coding 助手说“配置并启动 Tibo 监控”。助手完成以下操作，用户只填写两项凭据：

1. 检查 Node.js 20+ 和 curl，运行 `node "<skill>/scripts/background.mjs" prepare-setup`，在本机文本编辑器打开返回的 `monitor-setup.txt`。
2. 文档只有两个必填项：`DEEPSEEK_API_KEY`、`FEISHU_WEBHOOK_URL`。用户填写自己的 Key 和自己飞书群自定义机器人的 Webhook，保存后告诉助手“填好了”。文档说明提交并启动将产生少量 API 费用，并允许向这个机器人发送测试、额度与运行故障提醒；无需另填授权开关。
3. 运行 `background.mjs setup`。脚本校验并导入两项配置，执行 DeepSeek 的 4 个基础语义样例、采集检查和飞书连接测试，全部成功后加载系统后台任务。任一步失败都不会继续启动，配置和错误原因留在本机供排查。
4. 运行 `background.mjs status` 检查后台已加载，等待首轮 lastRun 成功再报告启用。用户无需编辑定时表达式、手动调用模型或维护 Codex 定时任务。

默认两项配置适用于未开启签名校验的飞书机器人。关键词规则如需配置可设为 `Tibo额度提醒`。如果机器人已经开启签名校验，必须在私人文档补充可选的 `FEISHU_SIGNING_SECRET`，这是飞书校验所需，不能只靠 Webhook 绕过。更新同一机器人的两项配置时会保留已有签名密钥。

所有凭据只由脚本读取，Agent 不读取或展示文档内容。导入成功删除临时填写文档，密钥转存到仓库外的私人文件。公开仓库与压缩包只有生成空白文档的代码，不包含任何人的已填写文档、Key、Webhook 或运行记录。

## 已有配置的单独测试与维护

已有飞书和 DeepSeek 配置无需重填。只更换 DeepSeek Key 时仍可使用 `background.mjs prepare-file` / `import-file`；只更换飞书可使用 `monitor.mjs prepare-file` / `import-file`。

用户仅要求测试时，不启动服务：`background.mjs check` 测试 4 个静态语义样例并记录少量真实 Token 用量，不发送额度提醒；`monitor.mjs probe` 和 `collect` 验证真实数据源；`monitor.mjs test-notification` 向已授权机器人发送明确标注的连接测试。基础样例成功不代表准确率保证。模型或源失败应报告故障，不能写成没有新帖。

## 从旧版 Codex 定时监控迁移

找到私人配置保存的旧 scheduleId，用宿主定时工具核对并暂停对应任务；不要改动其他任务。运行 `monitor.mjs pause`，保存旧的启用状态用于报告，但不能自动恢复用户明确要求停掉的任务。

保留同一个私人目录里的 state.json，因此历史游标、去重、已发送通知与待处理队列都能延续。不要清空记录来制造一次“成功运行”。用户只授权代码修改时，已安装 Skill 继续保持原版本并暂停，待真实测试通过后再更新。

## 安装和验证后台

用户授权更新与启动后，将已测试代码放在稳定的 Skill 安装目录。安装前检查差异，不覆盖用户自己的修改。私人数据始终在仓库和 Skill 之外，不复制到包里。

运行 `node "<skill>/scripts/background.mjs" install`。它检查模型样例验证、采集和飞书测试记录，生成用户级 LaunchAgent 配置，使用 Node 和脚本的绝对路径，再加载服务。安装器拒绝覆盖不同的已有配置。

默认每小时第 15 分钟执行，并在加载和用户登录时执行一次。休眠期间不运行，恢复后系统可以合并补跑一次；不是按漏掉次数无限补跑。启动后由已有游标补查数据源仍可获取的历史。没有自动防休眠，也不安装云端任务。

安装器不存储 Key 到 plist。可继承当前环境中无认证的本机 HTTP/SOCKS 代理；不复制浏览器 Cookie、系统登录凭据或其他项目的 API Key。无代理环境也必须验证实际网络路径。不要把“浏览器访问成功”当成后台已经可用。

运行 `background.mjs status`，确认 service.loaded=true，并等待 lastRun 有这次安装之后的成功结果。复核：

- 旧 Codex 任务已暂停，没有重复调度。
- 后台命令只有 Node 和 background.mjs，没有 Codex CLI。
- 待判断动态经 DeepSeek 分析，通知仍经过证据校验和去重。
- 没有新帖时模型 calls=0；有调用时返回真实 Token 统计。
- 退出 Codex 不会卸载这个用户级服务；电脑关机、注销或休眠则不能持续执行。

## 日常维护与预算

`background.mjs stop` 暂停并卸载当前服务；`resume` 恢复；`status` 检查结果。服务文件保留，因此暂停状态也会持久保存，重新登录不会擅自恢复发送。更换飞书机器人后重新测试；已有待发送消息会保留并使用新机器人，需告知用户。

每月预算默认为 8 元，按北京时间月份累计。已知调用使用服务返回的 Token 数与高峰价估算；结果不明的调用保留最大估算费用。预算不足时当前批次保留，后续采集可能等待该批次解除阻塞；恢复后从上次位置补查，不承诺预算耗尽期间持续完整入库。同一批次连续付费失败最多 3 次，避免无限重试。

当前价格依据：[DeepSeek 价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。2026-10-26 核验 Flash 高峰价：缓存输入 0.04、未缓存输入 2、输出 8 元/百万 Token。低峰实际费用更低；价格将来变化时需更新 deepseek.mjs 和估价说明，不把估算当账单。

公开发布前检查 allowlist、个人绝对路径和秘密模式，运行全部离线测试；真实测试记录和凭据不能打包。用户明确要求封装或上传时再制作压缩包或推送 GitHub，不自动发布未验证版本。
